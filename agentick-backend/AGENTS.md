# Agent conventions — agentick-backend

Scope: this file governs `agentick-backend/` only.

## Layout

Flat, not modular-monolith. One `app/{routers,models,schemas,core,db}` tree.
Do **not** split into `modules/<bounded-context>/{routes,services,repositories}`
until there are genuinely 3+ independent business domains — for a handful of
resources that structure is pure navigation overhead.

## Errors

Raise `app.core.exceptions.AppError` subclasses (`NotFoundError`,
`DuplicatedError`, ...) from routes instead of raw `HTTPException`. Add a new
subclass only when a route actually needs that status code — don't pre-build
the hierarchy for cases nothing uses yet.

Database-level failures that should become client errors are translated once,
globally, in `app/main.py` (`IntegrityError` → 409, `DataError` → 422) — not
per-route try/except.

## Response shape

Resources are returned directly at the top level of the response body (`AlertRead`, not `{success, data,
message}`-style envelopes). There is no list endpoint yet; when one appears, give every list the same pagination
shape rather than inventing one per route. Every documented 4xx/5xx response must declare a `model=` (see
`app/schemas/error.py:ErrorDetail`) — `.spectral.yaml`'s `error-response-has-schema` rule enforces this in CI, and the
schemathesis contract test fails on an undeclared status code.

## Models

Mix `app.db.base.TimestampMixin` into any model that needs `created_at`/
`updated_at` instead of redeclaring the columns. Keep integer (or native
`UUID`, never a 36-char string) primary keys — pick whichever a resource
actually needs, don't default to UUID "for consistency."

## Bounding untrusted input

Path parameters that are Plane work item ids are typed `uuid.UUID`, so garbage is a 422 from Pydantic. Any
path/query parameter that would flow into a SQL integer/bigint column needs an explicit upper bound
(`Path(le=...)`/`Query(le=...)`) so out-of-range input is a 422, not a 500 `DataError` from Postgres. Free-text
fields in bodies carry a `max_length` sized from real data (a TAWOS Sprint change line reaches 700 characters, so
the limit is 1000), not from a guess: a limit tighter than the data rejects real published alerts.

## Optional integrations (not implemented yet, but when one lands)

- Translate the third-party client's exceptions into `AppError` subclasses at
  the integration boundary (e.g. catch `httpx.HTTPError` inside the client
  wrapper, raise `ExternalServiceError`) — callers should never see a 3rd-party
  exception type.
- If the dependency is optional (feature flag / missing API key), guard the
  import with `importlib.import_module` + `try/except ImportError` and fall
  back to a no-op, rather than making it a hard `requirements.txt` dependency.

## Guardrails from community issues (not yet relevant, don't pre-build for them)

- **If request logging/tracing middleware is added later, don't use
  `BaseHTTPMiddleware`** — it can serialize `StreamingResponse` and silently
  turn the app sync under load. Use a pure ASGI middleware (`__call__(scope,
  receive, send)`) instead
  ([fastapi-best-practices#76](https://github.com/zhanymkanov/fastapi-best-practices/issues/76)).
- The SQLAlchemy `engine` in `app/db/session.py` is a plain module-level
  global, built once at import time — this is deliberate, not an oversight.
  With exactly one long-lived singleton and no hot-reload/multi-worker
  state-sharing requirement, wrapping it in `app.state` or a `Depends` +
  `lru_cache` provider would be indirection with no present benefit
  ([fastapi-best-practices#95](https://github.com/zhanymkanov/fastapi-best-practices/issues/95)).

## Auth

This backend has **no accounts and no tokens of its own for users**. Plane is the main system; this is an external
service next to it (an earlier scaffold had its own OAuth2 + JWT and a users table; both were removed):

- A user is whoever Plane says owns the `session-id` cookie. `app/integrations/plane.py` asks Plane who that is
  (`/api/users/me/`) and whether Plane lets them see the work item; a 401/403 from Plane becomes our 401/403. The
  service forwards only the user's cookie on those calls and only the bot's API key on writes.
- The offline research job proves itself with one shared bearer token (`INGEST_TOKEN`, constant-time compare in
  `app/core/security.py`). An empty secret never validates.
- Any new endpoint that touches a work item must go through the Plane access check; do not add a user table or
  roles unless Plane stops being the source of truth.

## Migrations

Never keep an autogenerated Alembic migration without reading its `upgrade`/
`downgrade` bodies. Verify `upgrade` → `downgrade` → `upgrade` round-trips
before committing.

## Tests

Real Postgres, no mocked DB (see `tests/conftest.py` — point `DATABASE_URL` at
a disposable container). TDD: write the test, watch it fail for the right
reason, then implement. `tests/test_openapi_contract.py` fuzzes every endpoint
against the app's own OpenAPI schema (schemathesis) — treat anything it finds
as a real bug, not a test to loosen.
